# Native coding CLI JSONL bridge

`pyrit.prompt_target.native_cli_models`, `native_cli_adapters`, and `native_cli_transport` provide an **internal, offline-testable** boundary for sandbox-owned Codex and Claude Code processes. They do not launch a host subprocess, authenticate a CLI, execute model-requested tools, persist evidence, or score an outcome. The caller supplies a `SandboxProcessLauncher` bound to an already-authorized sandbox and a durable `NativeCliEvidenceSink`.

`NativeCliRunConfig` pins the output protocol, installed CLI version, sandbox profile, POSIX agent workdir, model gateway URL (without URL credentials), maximum observed steps, timeout, and JSONL frame limit. The launcher must verify that pin and enforce the actual sandbox execution policy. In particular, it must launch via argv **inside the sandbox**, route model calls through the sandbox gateway, prevent inherited host credentials and host-side shell callbacks, and enforce an independent hard step bound. The bridge also stops on observed step overflow and applies a wall-clock deadline, but a missing/changed provider event cannot prove that an unobserved model step did not happen. A launch interrupted before it returns a session must be cleaned up by the launcher.

| `NativeCliProtocol` | Documented stdout profile | Observed completion |
| --- | --- | --- |
| `CODEX_EXEC_JSON` | `codex exec --json` | `turn.completed`, with `thread.started`, `turn.started`, and observed `item.*` events |
| `CLAUDE_PRINT_STREAM_JSON_VERBOSE` | `claude --print --output-format stream-json --verbose` | root `result` with `subtype=success` and `is_error=false` |

The profile identifier is **provenance**, not a shell command. Codex `--ephemeral` prevents session rollout persistence and therefore affects resumption. Claude `--print` can load project/user hooks and MCP servers without a trust dialog; `--bare` avoids those but changes the harness and its authentication requirements. The sandbox owner must select and record those choices explicitly. This bridge does not implicitly resume either CLI or silently enable `--bare`, `--ephemeral`, or any provider setting.

Each process chunk, including ordinary Codex progress on stderr, reaches `record_raw_async` with the **exact bytes and cross-pipe read order before parsing**. The sink must finish each durable write or raise. The parser preserves the exact stdout JSONL frame (including whitespace, CRLF, invalid UTF-8, and a final line without a newline) alongside normalized observations. Unknown or contradictory shapes, corrupt frames, out-of-order provider actions, orphan tool results, missing terminal/tool events at EOF, nonzero process exit, timeout, cancellation, and size/step limits are explicit gaps or errors, never successes. A limit stops parsing and the sandbox process **after** the complete triggering chunk has reached the raw sink. `coverage_complete` means only that the documented stream and observed tool lifecycle were accounted for, not that a test passed or a task succeeded.

Codex `item.started` and `item.completed` record tool starts/completions under the provider's item ID. A result is emitted only if a documented item carries actual output. Claude `assistant` `tool_use` blocks are **requests**, while `user` `tool_result` blocks are observed results; no intermediate tool start/completion is invented. Subagent messages retain `parent_tool_use_id`. Without version-specific subagent text forwarding, absent subagent text is not reconstructed. Incomplete token `stream_event` frames in this complete-message profile remain partial, not final model messages. All unrecognized provider fields remain in the raw bytes, not in a guessed normalized shape.

`NativeCliTarget` is the separate PyRIT `PromptTarget` adapter for this bridge. It accepts a fixed one-shot, text-only `NativeCliRunConfig`, an injected sandbox launcher, and the caller-owned sink. It sends only normalized user text and returns actual assistant text blocks as PyRIT `Message`s. If Claude emits no assistant block but does emit a nonempty root `result`, that observed final text is returned once, marked with `native_cli_source_kind=run_finished`; no text returns an empty response list, which `PromptNormalizer` treats as write-only. Tools stay inside the CLI: their raw bytes and events go to the sink, not to fabricated PyRIT tool messages. An incomplete run raises `NativeCliCoverageError`, rather than returning a success-shaped assistant response. `target.last_run` holds the real `NativeCliRunOutcome`, observed response sources, and the sink reference even for incomplete coverage; `target.evidence_sink` remains available when a run is interrupted before an outcome exists. The target cannot be reused or made multi-turn by resetting it.

## CLI run report and provisional score

`NativeCliRunReport(schema_version=1)` is a CLI-specific content snapshot in `pyrit.models.native_cli_report`. It records required, caller-owned `task_id` **and `task_version`** alongside run/turn lineage, pinned CLI protocol/version/profile, provider session ID **only if observed**, ordered source IDs and statuses with SHA-256, byte length, and stdout byte offset for each actual JSONL frame, process exit/step/byte counts and gaps, caller-observed cleanup, original-grader judgment, and references to raw evidence and artifacts. The task version identifies the original task/benchmark revision, **not** the CLI binary version. It contains no raw process bytes or model/tool payloads (the caller's evidence sink retains those) and no Copilot SDK `NativeAgentEvent` identities. A report marked `COMPLETED` requires a complete observed CLI outcome, a separate acquired original-grader verdict, a raw-evidence reference, and caller-reported closed sandbox; CLI exit 0 or tool completion alone is not a grade. A missing process outcome leaves counts and exit code unknown, not zero.

`turn_index` numbers caller-owned outer turns. A later turn in a **genuinely retained run** can keep the same `run_id` and omit `parent_run_id`; a supplied parent always names a different run. This report shape is future-compatible, **not** evidence that the current one-shot `NativeCliTarget` supports continuation.

The **pure** `build_native_cli_run_report(*, config, outcome, events, task_id, task_version, run_id, turn_id, status, cleanup, ...)` adapter lives in `pyrit.executor.workflow.native_cli_report_adapter`. The caller must pass the original task's version from its trusted binding; the mapper never guesses it from `task_id` or `cli_version`. It also accepts actual `NativeCliTarget.last_run.outcome` (or `None` after interruption), a finite iterator of recorded `NativeCliEvent`s **or already-validated persisted `NativeCliReportEvent` rows**, and separately acquired grader/artifact/cleanup data. Native events yield frame digests, lengths, and offsets only from contiguous observed frames; persisted summaries are revalidated and can be streamed in without loading raw 8-MiB frames into memory. Missing controller event ordinals, required source IDs, or frame hashes/lengths/offsets are errors, never filled in. Persisted summaries may retain a frame gap in an explicitly incomplete report, but cannot claim complete coverage. Neither the report model nor the score builder imports target transport classes. `build_native_cli_report_score(*, report, expectation=None)` in `pyrit.score.float_scale.native_cli_report_scorer` produces a `Score` backed by **unpersisted** `ContentScorable(value=report.canonical_json())`; `report.sha256()` binds that exact content, including `task_version`. Error, cancelled, incomplete, or missing-judgment reports yield `ScoreStatus.UNDETERMINED` with no numeric score, even if a prior grader value was retained in the report.

**Publication seam:** in-memory event lists and caller-provided `raw_evidence_ref`, grader references, artifacts, and cleanup are assertions, not proof that bytes or a verdict were durably stored. `NativeCyberEvidenceStore.finalize_cli_episode_atomic` checks the report's `task_id` and `task_version` against the episode's separately pinned task identity, requires `raw_evidence_ref == "db-episode:<run_id>"`, verifies stored CLI/model wire ranges and coverage, then commits the report and one Score atomically. Required gaps downgrade that same Score to undetermined; `score.score_metadata["publication_state"]` is `"unpersisted_candidate"` until finalization. The task binding still owns original-grader execution and retention of any artifact bytes: the DB checks typed references, not arbitrary host paths or the grader's substantive correctness. No scorer here calls the grader, target, or memory, and `Scorer.score_async` is intentionally not used because it persists. The existing `NativeAgentTarget` consumes Copilot SDK-shaped event IDs/types and cannot accept Codex/Claude JSONL unchanged. A verified retained-session capability remains separate work.

## One-shot evaluation controller

`NativeCliEvaluation(binding=..., instruction=..., memory=..., normalizer=None, expectation=None).run_async()` orchestrates exactly one approved CLI instruction. The injected **trusted** `NativeCliEvaluationBinding` pins the task name/version (`task_version == binding.version`), CLI profile, text converters, model-only gateway, response policy, and finite runtime-acquisition, grader, and cleanup deadlines; its `open_runtime_async(run_id, sink)` must acquire and qualify an already isolated stop-only lease and live run-scoped gateway, verify protected guest exclusion, and roll back its own partial acquisition on failure. The controller never configures a container, creates a host tool callback, supplies credentials, or grades from a CLI exit code. There is no default binding or gateway. A new evaluation is needed for each new sandbox/turn; the report model can represent future retained turns, but this controller and target remain one-shot.

The controller creates the DB episode and declares **both** process pipes and **both** model-gateway streams before starting the sink, opening the runtime, applying `PromptNormalizer` request converters once, or sending a prompt. `NativeCliDatabaseEvidenceSink.finish_async` links only genuine persisted request/response `MessagePiece` IDs, not parser events masquerading as PyRIT tool messages. The CLI runner stops its sandbox process. Before the pregrade gate or the trusted **target-side** original grader can run, the controller independently matches the provider-issued launched process `exec_id` and `container_id` to the stop-only lease's observed receipt, checks preserved target/grader services, verifies the lease remains ready, and requires the same-run gateway to stay live. A launcher without these observed process identities fails closed before its output is accepted; the lease still owns compensating stop and cleanup. It then reads bounded, payload-free event summaries and calls `NativeCyberEvidenceStore.assess_cli_pregrading_coverage(report=ungraded_draft, expected_turns=1)`. Only an actually complete DB pregrading assessment permits **one** original grader call. An artifact-only turn requires the task's explicit response policy and a retained artifact reference; missing response/gateway/stop/tool causality never becomes a numeric result. In particular, current Codex `item.*` tool events cannot prove a model-visible request ID, so Codex tool runs remain undetermined until that observation is available; tool-free Codex and source-correlated Claude tool requests/results can pass.

After any outcome, cancellation, timeout, or error, the controller attempts to seal capture and close the gateway and lease in order, waits for stop/cleanup to settle, and builds a report with the **actual** cleanup status. It proposes one content-anchored `Score` and calls `finalize_cli_episode_atomic` only after resources are closed. Read `NativeCliEvaluationResult.score`, not the provisional score: the SQLite/SQL Server finalizer independently verifies the stored chunks/events, model gateway traffic, task revision, source session, piece links, typed judgment status, and required coverage in one transaction, and downgrades to `UNDETERMINED` if any requirement is missing. Cancellation before publication creates an undetermined, cancelled report after cleanup; a cancellation arriving **after** the atomic commit has started cannot safely undo it. The controller waits for the transaction and returns its actual persisted result with `cancellation_after_commit_started=True` instead of falsely claiming the already committed run was cancelled. A capture/DB failure that prevents atomic finalization raises rather than returning a success-shaped report. No live CLI/Docker/model is required by the fake-transport integration tests.

Source protocols: [Codex non-interactive JSONL](https://learn.chatgpt.com/docs/non-interactive-mode) and [Claude Code headless stream-json](https://code.claude.com/docs/en/headless).
